四、结论

引擎层 MCode 明显占优：启动快约 9 倍（122ms vs 1130ms）、内存省约 4 倍（184MB vs 753MB）。原因清楚：MiMo 的 Bun 编译二进制把 SQLite/FTS5/全量 TUI 基建一次性拉起，且 Bun 运行时本身基线内存就高；MCode 的后端是纯 Node 模块图，按需初始化。
分发体积 MiMo 占优：96MB 自包含二进制 vs 369MB 的 .app——这是 Electron 的固定税（仅 Frameworks 就 262MB）。但两者的安装产物在同一量级（DMG 160MB 已压缩）。
注意口径：① MCode 引擎在独立 Node 进程中测得，未含 Electron 主进程与渲染进程（GUI 冷启动因单实例锁无法在本机无干扰测量）；② MiMo 侧为引擎二进制直测（launchers 的 0.6s 与引擎的 0.56s 基本一致，无额外开销）；③ 两者功能面不同（MCode 多了 GUI/Office/语音管线，MiMo 多了 FTS5 记忆库），启动负载不完全等价，比值仅供参考；④ 模型响应速度取决于 API 侧，与客户端无关，未测。

五、测试方法

MCode：startBackend("/tmp/mcode-perf-data") esbuild bundle 后以 node 22 直跑，performance.now() 计时，/usr/bin/time -l 取峰值 RSS，每次运行前清空数据目录。MiMo：bin/.mimocode serve --port 41xx，轮询日志至 "listening"，MIMOCODE_HOME 指向临时目录（首跑迁移完成后计时），getrusage(RUSAGE_CHILDREN).ru_maxrss 取峰值。环境变量注入均为临时目录，未触碰真实用户数据。
