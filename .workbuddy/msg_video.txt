MCode Remote: a video plays, from the other side of the gateway

The desktop answers a preview read of a video with `video: true` and no bytes -
its files tab plays the file from its own disk through the local preview
server (`officeServe`), so there was never anything to carry. A reader on the
pad has no disk to play from: the bytes are the only thing that can reach it,
and the answer carried none. `readPreview` now reads the file and rides the
base64 channel the pictures and sounds already use, under the same 25 MB
ceiling. The desktop never reads the field - its `mediaAddress` returns on
`video` before looking further - so the desktop is unchanged; the gateway was
rebuilt for it and restarted.

The phone takes the bytes, writes them to its cache, and plays them in a
VideoView with MediaController's transport - the same controls the desktop's
own bar offers, and no ExoPlayer dependency for the three formats every Android
build decodes. Over the ceiling says so instead of opening an empty sheet.

The project browser now opens files through the same openArtifact the artifacts
page uses: it carried a second copy of the read whose text-only branch handed
a video an empty sheet.

Verified on the pad against the live gateway: a 3-second clip copied into the
conversation's folder, opened from the project browser, and played in the
sheet. Both test files are deleted.
