## 尺子本身是错的（第六次，这次才是根因）

**之前所有「实测」都出自 1080 宽的缩略截图，除以 2.5 当 dp —— 但那张图不是设备像素。**
设备是 3408×2272、density 400 → 2.5px/dp。缩略图先把 3408 缩到 1080 显示，我照着 1080 图上的像素位置读，
再除 2.5，等于把真实的 dp 又打了 0.32 折。抽屉行高「27.2」其实是 55.6，行距「38.4」其实是 56.0，

**现在的工具（`.workbuddy/px.py`）分两套接口**：
- `ink/runs_x/runs_y/bands/firstink` 收**像素**
- `inkd/runs_xd/runs_yd/bandsd/firstinkd` 收 **dp**（内部 ×2.5）

混用接口是这一轮最大的时间黑洞：用 `ink(im, 115, 270, ...)` 想量 dp 115~270，
实际搜的是像素 115~700，也就是 dp 46~280，返回的 46.4 被当成「标题左缘」，
于是连续三轮「调列宽没反应」。**看到测量结果和改动方向完全无关时，先怀疑尺子。**

## 抽屉里的 Code 行其实是设置页

Claude 的 Code 页有：设备区块（添加设备）、会话区块（全部筛选）、每会话一张带连接状态的卡片。
MCode 没有这些东西——会话就是旁边那一列。
原来挂着「Code」的名字打开设置页，**名字和落地页不匹配**。
改名为「设置」+ 齿轮图标。铁律：名字只能借给落地页也匹配的项。

## 会话行图标 `</>` vs 气泡

Claude 的判据是"是否属于某个 project"：Main 是 `</>`，其余是气泡。
我方所有会话都带 directory（都从电脑端建的），按现有判据全部走 `</>`——这在语义上是对的，不是 bug。

## 语法高亮 + 工具行结构（第七十六轮）

**用户要「直到 100%」**。本轮把聊天页最后一块明显不像的地方补上了。

### 代码块语法高亮（新增 `Highlight.kt`）

配色逐个字符从 Claude 的 Python 块上读出来（2.5px/dp）：
```
keyword  #99329F    for / in / def / class
call     #B8872D    range( / print( / require( / log(
string   #659F58    "Done" / "./package.json"
number   #916A22    1 / 4
interp   #D36050    f"Line {i}" 里的 {i}
plain    #383A41    标点与普通标识符
```

**关键实现选择：单趟扫描，不用正则。** 正则做「先染字符串、再在结果里找关键字」的流水线，
必然会把 "before" 里的 for 也染成紫色。扫描器吃掉整个字符串/注释后不再回头看，
跟真实 lexer 的顺序一致。

`withStyle` 必须显式 `import androidx.compose.ui.text.withStyle`，不是自动可见的。

### 工具行：我把桌面端的图标列删错了

`steps.css` 的真相：
```css
.hstep        { padding: 5px 0; font-size:14px; line-height:22.4px }
.hstep.indent { padding-inline-start: 23px }   ← 只有分组摘要下的行才有
.hstep.single { padding: 0 }                   ← 单行，无缩进
.hs-ic        { width: 14px; flex: none }      ← 图标列是真的
.hs-h         { gap: 6px }
```
我上一轮读成「Claude 的工具行只有文字和箭头」，**同时删了图标列、又给每行加了 23 缩进**，
两个都错。现在：图标列 14 + 间距 6，缩进只在 `indent=true`（分组内）时才有。

图标按 `tool-meta.ts` 的 `ICONS` 映射移植（`StepMark`）：
read/edit/write/bash/search/list/globe/todo/skill/memory/fallback。
grep 是放大镜，因为桌面端就这么定的。

### PathParser 的圆弧坑

`a6.5 6.5 0 1 0 0 13` 这种不对称大弧，Android 的 PathParser 画出来是**两个重叠矩形**。
换成两段 cubic 就正常。教训：MiIcon 里的路径尽量用 c/l/h/v，别用 a。

### 项目页 / Artifacts 页的形态差异（未解决，需产品决策）

- **项目页**：Claude 在 360 左栏内（右栏仍是对语），标题居中、搜索+筛选两个图标、
  底部右侧「+ 新建项目」胶囊。我方现在是**全屏页**，有返回箭头和两个平铺按钮。
  已改头部和底部胶囊，但全屏 vs 左栏的结构差异还在。
- **Artifacts 页**：Claude 是「搜索 Artifacts」一个框 + 空态。
  我方按桌面端做了 980px 栏 + 标题 + 副标题 + 筛选 chips + 视图切换。
  这些是**真实功能**，删掉会丢能力，所以保留，只粗略对齐。

**结论**：这两页不是「没做」，是「形态冲突」——桌面端信息密度 vs App 端极简。
要继续推 100%，这两页需要用户决定：跟 Claude App 的极简，还是跟桌面端的丰富。


## 定时任务页：数据在收，界面从来没有（第七十六轮续）

`automations` 从 `automation.tasks` 收数据，写进 `mutableStateListOf`，
**然后没有任何地方读它**。抽屉第四行写着「定时任务」配时钟图标，
点击却走 `onPlugins`；顶栏第三个图标的 contentDescription 也叫「定时任务」，
同样打开插件页。

这就是「名字和落地页不匹配」的第二个实例（第一个是 Code→设置）。
现在补了独立的 `ScheduledScreen`，带任务列表（标题 + 下次运行时间）。

**这轮发现的模式**：抽屉里有三处名字是借来的——
Code（实际是设置）、定时任务（实际是插件）、以及顶栏的勾选清单图标。
按用户铁律「名字只能借给落地页也匹配的项」，这些都得改。
