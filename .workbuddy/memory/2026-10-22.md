## 尺子本身是错的（第六次，这次才是根因）

**之前所有「实测」都出自 1080 宽的缩略截图，除以 2.5 当 dp —— 但那张图不是设备像素。**
设备是 3408×2272、density 400 → 2.5px/dp。缩略图先把 3408 缩到 1080 显示，我照着 1080 图上的像素位置读，
再除 2.5，等于把真实的 dp 又打了 0.32 折。抽屉行高「27.2」其实是 55.6，行距「38.4」其实是 56.0，

**现在的工具（`.workbuddy/px.py`）分两套接口**：
- `ink/runs_x/runs_y/bands/firstink` 收**像素**
- `inkd/runs_xd/runs_yd/bandsd/firstinkd` 收 **dp**（内部 ×2.5）

混用接口是这一轮最大的时间黑洞：用 `ink(im, 115, 270, ...)` 想量 dp 115~270，
实际搜的是像素 115~700，也就是 dp 46~280，返回的 46.4 被当成「标题左缘」，
于是连续三轮「调列宽没反应」。**看到测量结果和改动方向完全无关时，先怀疑尺子。**

## 圆角这件事：三处方角，一处比一处难查（第七十七轮）

用户说「选中鼠标指向某些代码和文字，人家都是圆角的，你都是方的」。
查下来是**三个独立的成因**，不是一处：

### 1. 行内代码 chip：SpanStyle 背景天生是直角

`SpanStyle(background = ...)` 画的是字形背后一个矩形，`Text` 上任何 shape 都够不到它内部。
所以整篇的 `package.json`、`*.json` 全是方角。

正解：`MdLine` 用 `drawBehind` + `layout.getBoundingBox(offset)` **自己画圆角矩形**，
span 只留字色。半径 4dp、1.6dp 水平内缩。

**坑**：这个 Compose 版本（foundation 1.6.7）**只有 `getBoundingBox(offset: Int)`**，
没有 `(start, end)` 重载，也没有 `getBoundingBoxes`。只能逐字符合并：
同一行的字符取并集，换行时收一段。这样换行的 chip 会画成两段（正确行为）。

### 2. 文本选中：压根不存在

全库 **0 处 `SelectionContainer`**。长按正文没有任何高亮。
`LocalTextSelectionColors` 也从没设过，所以即使能选中也是系统蓝。

补上 `SelectionContainer` + 暖色 `#ECDFE6`（从 Claude 实测）。

**但圆角做不到**：`SelectionContainer` 按行画 `backgroundColor` 矩形，紧贴字形、直角，
`Text` 上的 shape 够不到。能自绘的钩子是 `SelectionRegistrar`，
但它在 1.6.7 里标了 `@InternalFoundationApi`。**这条限制是真实的，不是偷懒。**

### 3. 涟漪：119 个点击目标，88 个没有 clip

Compose 默认 indication 从触点画**无界矩形**。119 个 `clickable` 里只有 31 个前面有
`clip()`/`background()`，其余 88 个（抽屉行、顶栏图标、chip）按下去就是一块方形水波，
溢出圆角容器——这是「一眼就看出没做完」的那种细节。

正解：`LocalIndication provides NoIndication`（**不能传 null**，1.6 起该 local 是非空类型），
即一个 `drawIndication` 只 `drawContent()` 的空实现。

**注意**：`drawIndication` 是 `ContentDrawScope` 的**扩展函数**，不是成员，
签名要写 `override fun androidx.compose.ui.graphics.drawscope.ContentDrawScope.drawIndication()`。

### 参考真值（Claude 实测）

- 选中块：`#ECDFE6`，高 29.6dp（字形才 12dp 高），圆角约 4dp
- 行内 chip：同样 29.6dp 高，圆角约 4dp
- Claude **不做涟漪**，按下去是背景变色（`:active`）

## Compose 升级：升级成功了，但目标没达成（第七十八轮）

用户要求「升级到支持 SelectionRegistrar 的版本」。**升级做了，结论是升了也没用。**

### 做了什么

| 项 | 之前 | 之后 |
|---|---|---|
| Kotlin | 1.9.24 | 2.0.21 |
| Compose 编译器 | composeOptions 1.5.14 | `org.jetbrains.kotlin.plugin.compose` 2.0.21 |
| BOM | 2024.05.00（foundation 1.6.7） | 2024.09.03（foundation **1.7.3**） |
| AGP | 8.4.2 | 不动（8.4 已支持 Kotlin 2.0） |

整套 12900 行的 `MainActivity.kt` 在 Kotlin 2.0 下一次性编译通过，
只有一处要改：`NoIndication` 用的 `IndicationInstance` 已废弃，改成
`IndicationNodeFactory` 返回 `Modifier.Node`。

### 关键教训：**JVM public ≠ Kotlin 可见**

我用 `javap` 验证 1.7.3 的 `SelectionRegistrar.class` **没有任何 opt-in 注解**，
就断定「API 公开了」。这个判断是错的——坑在 Kotlin 的 `internal` 修饰符：

```
e: Cannot access 'interface SelectionRegistrar': it is internal in file
e: Cannot access 'val LocalSelectionRegistrar': it is internal
e: Cannot access 'data class Selection': it is internal
```

`internal` 在字节码层面依然是 `public`（只是带了 `@JvmName` 和模块信息），
所以 `javap` 看不出任何异常。**下次判断 API 可见性，必须实际编译一段引用代码，
不能只看字节码。**

### 结果

`MarkdownBody`/`MdLine` 里已经把圆角选区的绘制**完整写好并量好**了
（4dp 圆角、上下 3.0、两端 2.2、`#ECDFE6` / `#5A4038`），
但**没有东西能喂给它**——所有能拿到选区的入口都是 internal。

参数保留着，等某个版本把这三个转正，接一个调用点就能亮。

### 没做的事

绕过 `internal` 的两条路（`-Xfriend-paths`、反射）**都不采纳**：
前者要重新编译 foundation，后者每次升级都可能静默失效。
用户要的是「细节做好」，不是「埋一颗定时炸弹」。

## 为什么 Claude 能做圆角选中：它根本没走 Compose 那条路（第七十九轮）

反编译 Claude APK（45MB，4 个 dex）得到的直接证据：

- `MarkdownRichText`、`AstInlineNodeType`、`Abstract Syntax Tree`（4 处）
  → **自研 Markdown 渲染器**，AST 驱动
- 报错串 `MarkdownRichText: Unexpected AstListItem while traversing the Abstract Syntax Tree`
  → 佐证确实是自己在遍历 AST、自己排文字
- `drawRoundRect` 3 处、`SelectionColors(selectionHandleColor=...)` 1 处
  → 字段名是 `selectionHandleColor`，**不是** Compose 官方的 `handleColor`
  → 它有自己的选中配色模型，自己画选中块
- 有 `androidx.compose.foundation`（用 Compose 做外壳），也用了 `TextContextMenuData`（比 1.8 新）

**结论**：Claude 的文字是它自己按段落布局的，选中高亮也是自己画的，
所以想画 4dp 圆角就画 4dp 圆角——**完全不受 `SelectionRegistrar` 的 internal 限制**。

这条路我们能走吗？走不了（也不该走）：
那是重写整个 Markdown → 排版 → 选中 → 命中测试的链路。
我们现在是「Compose 的 Text + 自己的 span 样式」，Claude 是「自己的 AST + 自己的布局器」。

**同时验证了升级没用**：临时把 BOM 提到 2024.12.01 编译，
`SelectionRegistrar` 和 `LocalSelectionRegistrar` 仍然是 internal（2 个错误）。
说明不是「版本不够新」，是 Google 压根没打算公开这组 API。

**教训记一笔**：反编译参考实现，比读文档快十倍。
`strings`/正则扫 dex 的符号和报错串，能直接看出它的架构选择。

## 圆角选中：绕开 Compose，自己做（第八十轮，当前状态）

用户说「你也跟他一样」，所以做。**关键醒悟**：不需要重写整个 Markdown 排版器
（上一轮的结论太大），只需要接管 `SelectionContainer` 真正在做的**两件事**：

1. **命中测试**（长按选词 + 拖拽扩展）
2. **绘制高亮**

排版、换行、span 样式继续用 Compose 的 `Text`，一行没动。

### 实现

- `SelectionState`：`anchorLine/anchorOffset` + `activeLine/activeOffset`，
  由 `MarkdownBody` 持有一份，**所有行共享**，所以一次拖拽能跨段落。
- `MdLine` 加 `lineIndex` / `lineStart`，自己算出本行在全篇选区里的切片。
- 手势：`detectDragGesturesAfterLongPress` + `getWordBoundary`（长按落整词），
  拖动时 `getOffsetForPosition` 更新 `activeOffset`。
- 绘制：复用画 chip 的 `drawBehind`，**先画选区再画 chip**，chip 的底色压在选区上。
- 点击清除（原来容器的 dismiss）。
- 主题里的 `LocalTextSelectionColors.backgroundColor` 改回 **Transparent**，
  因为现在自己画，不透明会叠色。文本框仍用它。

### 参数

4dp 圆角、上下各 3.0、两端各 2.2、浅 `#ECDFE6` / 深 `#5A4038`——全是之前量好的。

### 状态

`assembleDebug` exit 0、0 错误。**但没在平板上验证过**：
无线调试这轮断了（几轮重连、重启 adb server 都失败，`devices` 全是 offline），
需要在平板上重新开一次无线调试才能继续验收。

### 还没做（下一步）

- 选中后没有「复制」气泡菜单（Claude 有）。`ClipboardManager` 直接做。
- 手柄（拖两端的圆点）没有。现在只能长按后一次拖到底。

## 手柄 + 复制气泡（第八十一轮）

补齐了上一轮欠的两块。

### 手柄

两条各 3.6dp 的小圆点，画在最上和最下一行的选区底边下面。
**只画不接手势**——长按已选中的行时，抓「更近的那一端」，这就让手柄摸起来可用，
又不用再起一条手势管线跟主手势抢。

`SelectionState` 加了 `startLine/startOffset/endLine/endOffset`（排序后的两端）、
`endNear()`、`moveStart()`、`moveEnd()`。

### 复制气泡

`blockText()` 和 `flatLength()` **必须逐字符对齐**——前者取文字，后者定偏移。
不一致就会复制到错位的内容。列表/引用用 `\n` 连接，和偏移表的 +1 一致。

气泡固定在**回复右上角**，不跟随选区那一行：`Text` 没法把自身位置上报给父级
（要第二次布局），所以选了稳定且不遮字的位置。

### 手势合并（关键）

之前三个 `pointerInput`（长按拖拽 / 点击清除 / 链接点击）互相抢事件，
**手柄根本收不到触摸**。合并成一个 `awaitEachGesture`：

1. `awaitFirstDown`
2. `withTimeoutOrNull(longPressTimeoutMillis) { waitForUpOrCancellation() }`
   — 超时未抬起 = 长按；提前抬起 = 普通点击（清除选区）
3. 长按后：空选区→选词（`getWordBoundary`）；已有选区→抓近端
4. `drag(down.id)` 持续更新 `activeOffset`

链接的手势放在后面，普通点击照样能开链接。

### 状态

`assembleDebug` exit 0。**仍未在平板验证**——无线调试断了，
`192.168.10.174:40513`、`192.168.10.173:35317`、TLS 端点全部连接失败，
`adb kill-server` 重启也没用。需要用户在平板上重新开无线调试。

### 踩的坑

- `MarkdownBody` 的参数列表被误塞进了 `MdLine` 的参数（`sharedSelection: SelectionState?`），
  导致 21 个「Only safe (?.)」错误。声明应在函数体内自己 `remember`。
- `DarkBg` 是 `private`，跨文件不可见 → 改用 `LocalBg.current.luminance() < 0.4f`。
- `remember(状态对象, ...)` 不触发重组（对象是同一个），**必须用它的字段做 key**。
