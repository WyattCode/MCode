## 连接泄漏：两端都没做存活确认（`ecdf030b` / `ee2f0d30`）

### 怎么发现的

受控实验：平板 USB 连着，用 `svc wifi disable/enable` 切断再恢复。然后对比**两端**的连接表：

```
桌面 netstat:          3 ESTABLISHED
平板 /proc/net/tcp:    1
```

多出来的 2 条是僵尸——平板早不用了，PC 进程还留着。而且**不会自己消失**，每次断线加一条。

### 根因

`ws` 只在收到 close 帧或系统发现断开时才触发 `close`。网络断掉**两个都不是**：连接半开，一直挂到 TCP keepalive 超时（默认 **2 小时**）。网关唯一的清理入口 `socket.on("close")` 永远不会执行。

**两端都没在确认对方是否还活着。**

### 修法

1. **网关**：每 30s ping 所有 phone，连续两轮没 pong 就 `terminate()`。用 `WeakMap` 存存活状态（避免 bookkeeping 反过来吊住 socket）。
2. **平板**：`close()` → `cancel()`。`close()` 是协议消息，要对方同意；对方已死就石沉大海，TCP 记录留着。

### 验证（要两端都看！）

| | 断开前 | 断开中 | 恢复后 |
|---|---|---|---|
| 旧版 | 1 | — | **2** ❌ |
| 新版 | 1 | **0** | **1** ✅ |

### 教训

**心跳的误报**：日志里 `sent ping but didn't receive pong within 20000ms (after 82 successful ping/pongs)`，紧接着 1 秒后 `ws open`——**连接本来是好的**，桌面端只是在初始化 providers。20s 太紧，改 30s，与网关清扫周期对齐。

**测试写对了才知道代码对不对**：第一版清扫测试用原始 socket，写完 upgrade 请求就立刻 `pause()`，结果 101 响应被吞掉，网关根本没把它当 phone——测试失败但**原因是错的**。必须等 101 到达再静默。

**打包产物 ≠ 源码**：桌面端跑的是 `AppData\Local\Programs\MCode\resources\app.asar`。改了 `src/` 不重新 `npm run package:win` + 安装，行为不会变。验证方法：`grep -c "sweepIntervalMs" app.asar`。

## `unref()` 让清扫在需要时停摆（`7d0188dd`）

上一轮的清扫**实际没生效**，因为末尾写了 `sweep.unref()`。

`unref` 看起来天经地义（守护定时器不该挡住进程退出），但 Node 在**没有其他活跃句柄时会跳过该轮**。诊断输出：

```
[sweep] round: 1 phone(s)  x9     ← 有手机连着并应答
[sweep] round: 2 phone(s)         ← 静默手机加入
... 然后 2.5 秒内什么都没有
```

两轮之后就静默了，而**生产里这个状态正是"所有手机都不说话了"——恰恰是清扫唯一该工作的场景**。旧代码在最需要它的场景里完全不干活。

`close()` 里已经 `clearInterval`，所以去掉 `unref` 不会有定时器泄漏到进程之外。

### 教训

**`unref()` 不是无副作用的性能优化**。它改变的是「这个定时器还算不算活跃句柄」，在**空闲场景**（也正是守护定时器最需要工作的场景）会让回调不被调度。

### 顺带：给广播组加了上限

`phones` 是广播组（每帧发给所有连接），原来**无上限**。填满它的方式不都是攻击：平板重连快过清扫、浏览器标签页停在配对地址上、读者走开后机器还在重试。

上限 8，第 9 个连接 `close(1008)` 并打日志——**让失败可见，而不是悄悄变成扇出成本**。

### 测试自己踩的两个坑

1. 静默 socket 用 `once("data")`，在第一个分段就解绑，101 还没确认 → 网关**从来没把它当成 phone**，清扫自然没东西可清。要用 `on`。
2. 上限测试继承了前面的 `phone` 连接，所以"第 9 个"其实是第 11 个。要显式关掉。

两个都是「测试失败但原因是错的」，只有看日志才分得清。

## 四个浏览页在平板上空 74%（`ba455d17`）

### 现象（实测）

项目 / 定时任务 / Artifacts / 插件 四页，在平板上被钉在 26.4% 的左栏（900px），**右栏 2508px 里 0 个元素**——纯黑。

代码注释说这样设计是"让对话仍留在旁边"，这在**有对话时**成立，但这四页是浏览界面，不是边聊边看的东西。

### 修法（两行）

```kotlin
val isFullScreenPage = leftMode == Projects || Scheduled || Artifacts || Plugins

// 左栏
Column(Modifier.weight(if (isFullScreenPage) 1f else leftFraction) ...)

// 右栏：不组合，而不是画个空的
if (!isFullScreenPage) Column(Modifier.weight(1f - leftFraction) ...)
```

**关键点**：右栏必须**不渲染**。`weight(1f - leftFraction)` 的 Column 收不到 0 宽，它仍会占掉那 26.4%。

### 验证

- 定时任务空状态居中，主按钮在右下角

## 硬编码 tint 与触摸目标（`2248c0d0` / `642d3b66`）

### 两个顶栏图标在深色下隐形

## 页头对齐、竖屏走查、标题被空 Spacer 吃掉一半（`b8b442e2` / `2ddb8687`）

### 两个页头不在一条线上

**判据：没写高度的那一侧就是错的那一侧**——52 不是设计出来的数，是 padding 落出来的。

### 竖屏走查（2272×3408，强制 `user_rotation=0`）

竖屏暴露的真问题：**会话标题被截成 `New se…`**。

### 空 Spacer 吃掉一半标题宽度（重点）

```kotlin
Text(title, modifier = Modifier.weight(1f, fill = false))   // 权重 1
Spacer(Modifier.weight(1f))                                  // 权重 1 ← 无条件
if (!flat) Text(relTime(...))                                // flat 行时间在标题下方
```

**两个 weight(1f) 平分行宽**。flat 行的时间画在标题下面，这个 Spacer 什么都不推，纯占一半。

实测印证：行内宽 428px，标题得 **214px（正好一半）**，旁边 214px 空着。

改 `if (!flat) Spacer(...)`。

**这不是竖屏专属**：横屏下 360dp 的左栏只给标题 151dp，本可用 302dp。只因当前名字短才没露馅，第一个长标题就会露。

验证：竖屏 `New session` 108dp、`Test message` 118dp，均完整。

### 又确认不是 bug 的两处

- **正文 start 48.8dp / end 21.6dp 不对称**——注释说右边留给手势条，实测 122px/54px 完全吻合
- **竖屏消息顶部看着被切**——列表已滚动，首行滚到容器上边缘被裁，正常滚动行为

### 各屏幕下左栏可用宽度（`leftFraction=0.2641` 固定比例，无断点）

| 场景 | 屏宽 | 左栏 | 标题可用 |
|---|---|---|---|
| 手机竖屏 | 360dp | 95dp | 37dp ← 不可用 |
| 平板竖屏 | 909dp | 240dp | 182dp |
| 平板横屏 | 1363dp | 360dp | 302dp |

**没有一个宽度断点**，`leftFraction` 是常量。手机竖屏下这套几何是塌的，但那个尺寸不在本项目目标设备内。

## 页头对齐、标题截断、对比度（`b8b442e2` ~ `72f6645e`）

本轮 7 个修复。新增两个检查工具，以后这类问题不用再靠肉眼。

### 新增工具

**`node scripts/contrast-check.cjs shot.png shot.xml`** — 从截图 + uiautomator dump
读每个文本节点的对比度，按最差排序，低于 4.5 时 exit 1，可做门禁。

**`npm run androidtheme`** — 从 Kotlin 源码检查颜色常量：`Dark*` 是否等于其浅色
孪生、文字色是否在其实际背景上够 4.5（含 `Fg`/`Bg` 配对判断）。

### 查出的真问题

**1. 左右页头不在一条线上（`b8b442e2`）**
左栏显式 `height(63.2.dp)` 中心 161px；右栏没写高度，自然落成 52dp 中心 147px。

**4-7. 四处对比度不足**
- 免责提示 `.copy(alpha=0.75f)` → 浅色 **3.68**，改原值 6.67
- 代码块文字 `.copy(alpha=0.8f)` → 浅色 **3.97**（11sp 小字！），改原值 6.28
- `DarkToolWhat = 0xFF5C5C57` **等于浅色值** → 深色 **2.74**，改 `0xFF97958E` = 6.15
- diff 胶囊 `+519` **2.60** / `-7` **3.80**，改 `#2E6B2B`/`#A02A47` = 4.83/5.25
- 「思考中…」`0xFFBD6F50` 浅色 **3.75**，改分主题 `#A85A3C`/`#E08A63` = 4.97/6.91

### 反复出现的模式（5 次了）

**在 `LocalMuted` 之上再叠 alpha**。muted 本身就是给次要文字的低对比色，再乘
0.75/0.8 就跌破 4.5，**而且只在浅色跌破**——深色底够黑，同样的 alpha 反而没事，
所以深色检查永远发现不了。

**`DarkToolWhat` 那条最值得记**：注释就写着 `dark: (151,149,142)`，紧挨着的常量
却是 `0xFF5C5C57`（浅色值）。**注释对、代码错**，和记忆里那条一致。

### 工具的坑（两次假阳性）

**对比度脚本第一版取框内最亮/最暗像素当墨色** →
- Artifacts 页报出 1.00:1：Compose 语义树把同一元素报了两次，bounds 交错
  （`Artifacts` 有 y 131..146 和 146..206 两份），15px 那个采样落在字间空白。
  修：跳过高度 < 20px 的框（11sp 也有 34px）。
- 「已编辑」报出 2.07:1：取最亮像素取到了**卡片白底**，不是字形。
  修：底色改取**框内众数**（文字永远只占矩形小部分），墨色取直方图**细尾**。

精度用 64 灰度桶，误差约 2%（3.68 读作 3.77）。三段回归都验过。

### 过滤态的空文案说错了

「只看运行中」开着且没有运行中的会话时，列表说「还没有对话」——**但机器上有两个**。
调用方已经过滤掉了，列表分不清「没有会话」和「没有被过滤出来的会话」。

加 `runningOnly` 参数，说「没有运行中的对话」。**这是这个空状态块的第四种情况**
（断线 / 过滤 / 真空 / 搜不到），前三种都是见到错误文案后才补的。

### 走查方法

**批量脚本比逐页手点可靠**：10 个组合一次跑完，2 分 20 秒，不会漏页。

**JS 里 `a + cond ? x : y` 的优先级坑**：`+` 比 `?:` 高，会得到 `"str"...` 再判断，
输出标签全错。我因此误判过一次「输入框有 7 个」。

**搜索框要先确认 `mInputShown=true` 再输入**，否则 `input text` 落不到框里，
看起来像「搜索不生效」。
