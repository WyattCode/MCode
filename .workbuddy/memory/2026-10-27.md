### 先推翻上一轮记下的缺陷

上一轮 PORT-STATUS 写着「`ses_01a1505e372a` 105 条消息只渲染 1 条，数据缺陷」。
本轮写 `.workbuddy/probe-get.mjs` 直接走 ws 问网关：

- `session.get ses_01a1505e372a` → **返回 105 条**，43 user / 62 assistant，顺序正确
- 用同样的 payload 过一遍行规则 → **138 个可见元素**（103 消息行 + 33 工具行 + 2 错误卡）
- `session.get ses_01a1505dfc0c` → 返回 **1 条**，而它的磁盘上也只有 1 条

真因：抽屉里有**两条同名「来自手机 (分支)」**，`8ec9a9` 是 105 条（10-20）、`3ed3c3` 是 1 条（10-19）。
我把行映射到了错误的 y，打开了 1 条那个，把它的单条气泡读成「105 条坏了」。

**标题不标识行。** 按 `updated` 排序、从顶部数、对上 session id，再下结论。

### 工具摘要行：四处口径漂移，全在「怎么数」不在「怎么画」

| | 原 | 现 |
|---|---|---|
| `glob`/`grep` | 计入 read | 独立 search 桶，「已搜索 N 次」 |

| 失败 | 追加「（N 个失败）」 | 不写进文字（桌面端用图标） |
| 分隔 | `, ` | `·` |

口径来自桌面端三个文件：`tool-meta.ts` 的 `bucketOf`、`step-rows.ts` 的 `groupSummary`、
`i18n.ts` 的 `buildWorkDisplay.*`。**没有自己编文案。**

### 真机验证（决定性证据）

手机端渲染出两组折叠步骤：

- **「已搜索 2 次」**
- **「已读取 resources/skills/visualizer/SKILL.md」**

旧代码第一行会是「读取了 2 个文件」。

## 定时任务双胶囊；项目页字号；两个"无参考件"的页面（第一百四十轮）

### 110.4 vs 122.8 的真相：页面上有两个胶囊

文档里带着好几轮的「110.4 vs 122.8，12 的来源未定位」。
**根因不是挤压，是 `ScheduledScreen` 里画了两个胶囊**：

- 空态分支内一个 Box（「+ 新建任务」122.8×43.6）
- 函数末尾一个 Row（图标 + 「新建任务」，pad 撑出 110.8）

截图里两个都画出来了，y 1373 和 y 2121。参考件只有一个，在页面底部。
删掉空态里那个 → 实测 121.6（差 1.2 是圆角抗锯齿）。
**两个读数本来就来自两个不同的盒子。**

### 连带发现的第二个 bug：宽屏渲染两遍

`ScheduledScreen` 的全屏分支写的是 `if (widthSize < Expanded) return`，
宽屏时不返回 → 继续走双栏分支，又画一遍。
改成无条件 `return`（设置页早就是这么写的，注释里也早写明了）。

### 项目页标题：我把方向改反了一次

| 步骤 | 字号 | 墨迹 | 判断 |
|---|---|---|---|
| 原 | 17.2sp | 17.2 | 比参考 15.2 大 → 改成 15.2 |
| 改后 | 15.2sp | 11.2 | 又太小 |
| 最终 | **16.8sp** | **12.8** | ✓ |

**错在拿不可比的数字相减**：参考是「如何使用 Claude」（中文决定墨迹），
我是「X-SSH」（纯拉丁，无降部）。
改用**两边都有的拉丁字形**比：参考「Claude」12.8 vs 我「MCode」11.6 @15.2sp
→ 15.2 × 12.8/11.6 = 16.8。实测 12.8，精确命中。

**这是本项目第二次犯「跨字形墨迹相减」的错**（第一次是标题宽度）。
