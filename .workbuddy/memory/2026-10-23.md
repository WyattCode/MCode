### 重构：选区抽成 `Modifier.selectable`

原来 wash / 手柄 / 手势两百多行全在 `MdLine` 内部。代码块要同样的能力，
复制一份必然漂移，所以抽成：

- `Modifier.selectable(laid, sharedSelection, lineIndex, lineStart, slice, text, onPlaced)`
- `DrawScope.drawSelectionWash(laid, shared, lineIndex, slice)`
- `codeSelection(shared, lineIndex, lineStart, length)` —— 切片计算

段落、列表项、代码块三者共用同一套几何。

### 顺带暴露的三个隐藏 bug

1. **`lineStart` 语义错误（最严重）**：这一字段原本传的是块在**整篇**里的
   偏移（`offsets[index]`），但切片逻辑需要的是「这个 `Text` 在**块内**的
   位置」。混用导致每个段落的切片起点都越过了自己块的末尾 ——
   **除了列表，什么都选不中**。现在所有调用点传 0，列表内部按项累加。
2. **末端手柄画在第一行**：`chipBoxes` 对折行的段落返回多个 box，
   拿 `boxes.firstOrNull()` 当两端，使长段落的两个手柄都出现在顶部。
   改为 start 用第一个 box、end 用最后一个 box。
3. **列表项拖不出去**：列表项共享同一个块索引，`lineIndex + steps`
   会原地踏步。步骤现在跳到**块**。

### `armed` 是死状态

`选择文本` 菜单项写了 `armed = true`，但**没有任何地方读它** ——
点了等于没点。现在 `selectable` 里读：armed 时一次普通按下即选词，
不再等长按超时（菜单刚提示过「长按或拖动选择文字」，再要求长按是重复劳动）。

### 气泡靠近顶部的处理

原来只有 `coerceAtLeast(0)`，选区在屏幕顶部时气泡被压到 y=0，
**盖住它要操作的文字**。改为：上方放不下就翻到选区下方
（48 胶囊 + 8.4 间距 + 27.6 色块高）。

### 表格偏移是最麻烦的一处

单元格是「长文本里的一个小片段」，和列表同构但二维索引。
`tableCellStarts(head, rows, columns, base)` 按 `blockText` 的真实拼法算：

`(head + rows).joinToString("\n") { it.joinToString(" ") }`

- 行内单元格之间 **1 个空格**
- 行与行之间 **1 个换行**
- **这两个分隔符不属于任何单元格**

把它折进单元格长度，后面所有单元格就整体右移一位 —— 选中错字，但只在真机上才看得出来。

抽成纯函数后写了 6 个测试。**故意把分隔符折进去，5 个测试同时失败**
（`aTwoColumnTable` / `theSeparatorsBelongToNoCell` / `theTableMatchesItsOwnFlatText` /
`threeRowsAdvanceByTheirOwnLengths` / `aShortRowPadsItsMissingCells`）。

### 写测试时自己算错两次

第一个 `aTwoColumnTable` 期望值手算成 `[5,8]`，实际应为 `[4,7]` ——
`"a b\ncc dd"` 里 `\n` 在索引 3，行从 4 开始。
**教训：期望值不要手算，从真实拼接的 flat 字符串 `substring` 反推。**
后来的测试都改成「先构造 flat，再断言 `flat.substring(start, start+len) == cell`」。

### 顺手修掉的两个真 bug

1. **引用块里的表格完全消失**：`when` 没有 Table 分支，`else -> Unit` 吞掉了。
   不是「选不中」，是**根本渲染不出来**。
2. **锚点上报重复三份**（`MdLine`/`CodeBox`/即将加的表格）：抽成
   `rememberAnchorReporter(sharedSelection, lineIndex, slice, laid)`，
   返回 `onPlaced` 回调。放置坐标进 state、按选区跑 effect、位置真变了才 tick++。

### 1. 已有选区时，抓手柄要再长按 500ms —— 修掉

参考里手柄画成两个大圆，意思就是「可以抓」。原实现一律
`awaitLongPressOrCancellation`，每次微调都要先等半秒。

现在 `grab` 条件成立时直接 `down`：
- `armed`（菜菜单选了「选择文本」）
- **按在某一枚手柄上**（`onHandle`，命中半径 18dp = 36dp 直径，平台建议最小触控）

按在选区内、但不在手柄上 —— **不**立即响应（那要么是轻点=取消，
要么是滚动；从中间抓会把选区塌成一个字）。

### 2. 画的和能抓的必须同源

`handleCentres(laid, shared, lineIndex, slice, density)` 同时被
`drawSelectionWash`（画）和 `onHandle`（命中）调用。
以前两处各算一遍，是「画在一处、抓在另一处」的经典来源。

几何数值全部提到常量区：`HANDLE_DISC 12.6` / `HANDLE_OVERLAP 1.6` /
`WASH_SIDE 0.8` / `WASH_INSET 1.2` / `WASH_CORNER 4.dp` / `HANDLE_REACH 18`。

**注意 Compose 的陷阱**：`TextLayoutResult` 没有 `density` 属性。
第一版写了 `laid.density` 编译不过，改成显式传 `density: Float`
（Composable 里取 `LocalDensity.current.density`）。

### 3. `endNear` 的比较器是错的

旧实现：`abs(line-startLine)*1000 + abs(offset-startOffset)`。两个问题：

- **块严格在两端之间时**，它会算成「离哪端数字更近」，而不是「这是拖动中」。
- **表格所有单元格共享同一个 block 索引**，整张表算出来分数相同。

改成按块内偏移比较，抽成纯函数 `nearerEndIsEnd(...)`，加 8 个测试。
故意改回旧比较器 → `aBlockBetweenTheEndsExtendsTheEnd` 失败。

⚠️ 注意：表格同块那个场景旧实现**恰好也过**（偏移差 < 1000 时权重不起作用）。
所以那组测试里真正守住旧 bug 的只有 `aBlockBetweenTheEndsExtendsTheEnd`。
写这类测试要挑能真正暴露问题的数值，别挑「顺手也过」的。

### `dragSteps` 修了一个真 bug，测试又抓出一个

原实现用 `current.size.height`（整个 `Text`）当步长：

教训重复第三次了：**期望值从定义推导，不要靠「看着像」。**

### 真机抓出 4 个代码审不出来的 bug

1. **全选直接崩溃**（最严重）
   `offset(103) is out of bounds [0, 103)`。
   原因：`chipBoxes` 收到 `0 until length`，但 `getBoundingBox` 只接受
   `[0, length)`。全选把终点设成块长度，正好越界。
   而这段跑在 `drawBehind` 里 → **整个进程挂掉**。
   修：`clampToLayout(range, length)` 纯函数 + 7 个测试。

2. **抓手柄后手势被滚动抢走**
   抓住了圆盘，但 down 事件没 consume，父容器第一次 move 就接管
   （日志里能看到 `SCROLL_EVENT`）。表现为：选区只动一行，手指继续走但没反应。
   修：`if (grab) down.consume()`。

3. **「回到底部」浮动按钮盖住右手柄**
   两者都在底部中央。用户看得见选区却抓不到手柄。
   修：给 `Timeline` 加 `selecting: Boolean` 参数，选区激活时按钮让位。

4. **抽屉打开后气泡变僵尸**
   双击面板滑出抽屉时，内容左移，但 Popup 在独立窗口、锚点还停在旧坐标
   → 气泡浮在侧栏上，下面没有任何选区。
   修：`LaunchedEffect(drawerState.isOpen)` 打开即清空所有选区。

### 我在这一轮走了两个弯路，都要记住

**弯路一：用色值掩码找手柄是错的。**
代码高亮主题里 `#AE6B4E` 这个棕色同时也用于字符串/数字 token。
按颜色扫描会把 `"zh_CN"`、`1000` 这些文字当成手柄，得到一堆 1px 的假簇。
**正确做法：连通域分析 + 尺寸过滤**（≥30×30px 才算圆盘）。
已写 `.workbuddy/handles.py`，实测两个圆盘都是 **61~62px = 24.4~24.8dp**，
与目标 25.2dp 一致。

**弯路二：把「拖动没变化」误判成「功能失效」。**
真实原因是：
- 第一次拖动起点 y=1409，而手柄中心在 y=1339，**低了 70px，落在圆盘外**
- 抓到的是起点手柄时，往右拖会让选区**变窄**（activeOffset 逼近 anchorOffset）

所以「拖动无效」有三次都是**起止点选错**，不是代码问题。
教训：**先定位准目标，再判断功能成败。** 这和「小截图会骗人」是同一类错误的两个面。

### 加了什么

`everyCellAgreesWithItsOwnFlatText` —— 表格偏移的**不变量**：

对 6 种表格形态（最小表、2×2、短行、超长行、空单元格、混合宽度），
每个格子的偏移必须能从 `blockText` 生成的 flat 串里**切出它自己的文本**。

这是真正的风险点：`tableCellStarts`（按行遍历）和 `blockText`（joinToString）
是**两条独立代码路径算同一个布局**，不一致时冲刷会偏一个字符，
编译器、类型系统、截图三者都发现不了。

另有 `adjacentCellsHaveExactlyOneSeparatorBetweenThem` 直接断言分隔符间隙。

### 验证测试有效性时，踩了一个新坑

第一次「故意改坏」：把 `at += len; if (...) at += 1`
改写成 `at += len + (if (...) 1 else 0)` —— **语义完全等价**，测试全绿。
这不是测试失效，是我的改动没破坏任何东西。

第二次改成真的破坏（删掉行间换行推进），

## 新建会话的三处缺陷（第九十五轮）

用户要求「继续，直到完美」，于是去修上一轮发现的侧栏标题问题。
一查之下，`新建会话` 这个按钮其实是**三重坏掉**的。

### 1. 标题被硬编码锁死

`session.create` 带了 `title: "来自手机"`。而服务端
`src/server/session/title.ts` 的规则是：**没有标题才自动命名**
（首条消息首行作 fallback，后台再用模型命名）。

带了标题 = 永远不生成 → 十几天来所有手机端会话都叫「来自手机」，
侧栏变成一堆无法区分的行。

修：**不传 title**。实测验证链路：

| 时刻 | 磁盘上的 title |
|---|---|
| 刚创建 | `"New session"`（服务端默认值）|
| 发一条 `hello-there` 后 | `"hello-there"`（首行命名）|
| 模型后台命名后 | `"Greeting"` |

`cockpit.html` 里同一行也是硬编码，一并修了。

### 2. 新会话不进入侧栏

`select(sid)` 只在 `session.get` 返回时才 add 行，那是**一个来回之后**。
实测：磁盘上已有 3 条会话，侧栏仍只显示旧的。

修：直接用 `session.create` 的返回**立即插入**列表头部（`sessions.add(0, row)`）。

### 3. 会话建到了错误的目录

`newSession()` 不传 directory 时用服务端默认 `D:/Apps/MCode`（安装目录！），
而侧栏是按目录过滤的 → 新会话建在了列表**看不到**的地方。

修：默认取当前打开会话的 `directory`。

### 副产品：`cockpit-html.ts` 的生成器

该文件头部写着「edit cockpit.html and re-run the generator」，
但**生成器从未提交过**。写了 `.workbuddy/gen-cockpit.py` 补上。

### 教训回顾

这一轮的三个 bug **全都是「用户可见功能完全失效」级别**，
而且都在我上一轮「验证通过」的功能旁边。
说明**只验自己改的那一块是不够的**——用户真正用的是整条链路。

### 测试会话清理

验证时建了 3 个空会话，用完删掉了。误触弹到 `Greeting` 的删除确认，已取消。

## 平板防休眠：adb 循环保活行不通（第一百零六轮结论）

### 试过并失败的

1. `settings put system screen_off_timeout 2147483647` —— 值写进去了，
   `mScreenOffTimeoutSetting=2147483647` 也认了，**但屏幕照样睡**
2. `svc power stayon true` —— `mStayOnWhilePluggedInSetting=15`（全类型），
   仍睡，因为**平板没插电**（`AC/USB/Wireless powered: false`）
3. `locksettings set-disabled true` + `lockscreen.disabled 1` —— 锁屏解除了，
   但**屏幕背光不亮**
4. `.workbuddy/keepawake.py` 每 20 秒发 `KEYCODE_WAKEUP` —— 命令全部返回成功
   （日志一路 `nudged`），**屏幕依旧黑**
5. `am start -n com.mcode.remote/.MainActivity` —— 也点不亮

### 结论

**不充电时安卓会忽略所有软件唤醒手段**，只有物理按键或充电能点亮屏幕。
`stay_on_while_plugged_in` 是唯一可靠机制，但它**必须有电源**。

→ **别再用 adb 循环保活**，浪费 token 且无效。
→ 正经解法：**插上电源**，然后 `svc power stayon true` 就永久生效。

### 附带

无线调试端口会漂移（42407 → 35909），`adb connect` 报
"目标计算机积极拒绝" 时不要以为设备离线，问用户当前端口最快。
