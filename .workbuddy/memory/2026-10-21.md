### 破案方法（重要，可复用）

**症状**：编辑卡片 `editedOf` 日志始终 0 次，明明会话里有 `edit`/`write` 调用。

**误判过的方向**：以为渲染路径漏接（`Step`/`ToolRun` 折叠绕过调用点）。改了一圈仍为 0。

**真因**：读错字段。桌面读 `metadata.diff`，我读 `state.output`。
**验证脚本**：写了 `.workbuddy/scan-all-meta.mjs` 遍历所有 session 统计 —— 1306 次工具调用 / 244 次有 `metadata.diff` / **0 次** output 里有补丁。

**结论**：`metadata` 挂在 part **顶层**，不在 `state` 内。实测形状：
`{type,id,callID,name,status,input,time,output,title,metadata}`，`metadata` 的键是 `path,diff,filediff,occurrences`。

**教训**：怀疑「没渲染」之前，先证明「数据到了吗」。写一个遍历全部会话的统计脚本，比在渲染代码里猜快得多。

### 本轮修的坑

1. **`Box` 会层叠**：行容器是 `Box`，新加的卡片叠在段落上而不是接在后面（截图「起更新了。」被压住）。要 `Column`。
2. **回合边界**：`turnEdits` 里若让 gap/err 也能更新 `last`，卡片会挂在失败提示后面。只有 `Item.Msg` 和 `Item.Tool` 才算。
3. **grep 的 pattern 不是文件**：来源列表把 `*(HANDOVER,handover,...)` 当文件列出来。只有 `read`/`list` 的 `file_path`/`path` 才是。
4. **`deliveredOf` 只问顶层 `metadata`**：历史会话的 part 可能把它放在 `state` 下，两处都要问。
5. **同一个「折行绕过」病第二次**：`DeliveredCards` 也因为只传给裸 `is Item.Tool ->` 分支而永不显示。凡是依赖「某个参数只在某个分支传入」的渲染，都要检查折叠。

### Kotlin/Compose 踩坑

- `Icons.Outlined.Info` **不存在**（material-icons-extended 里也没有），要用 `MiIcon` 手绘路径。
- `Dp * Float` 合法，`Float * Dp` 不合法；`Dp + Dp` 合法。写 `narrow + (wide - narrow) * factor` 而不是 `factor * (wide - narrow)`。
- `detectTapGestures` / `tryAwaitRelease` 需要 `import androidx.compose.foundation.gestures.detectTapGestures`。
- 改大块 Kotlin 结构时别用 Edit 拆注释块——这次把 `/** ... */` 拆成两半导致编译失败，得手工补回。

## 错误行 / 通知行（ErrorStep + NoticeRow）

两项都是「`.hstep` 14/22.4、上下 5、14 宽标记列、`!` 或 `i` 等宽字」。

**通知行**：条件 `metadata.interactive === true`（模型给 bash 传 `interactive: true` 时，`src/server/tool/bash.ts:465` 写入）。要幂等——流式会把同一个 part 发很多次。用 `uid = "int.$callId"` 去重。已验证：真机造一次真实交互式调用，行正确显示。

**错误行**：带 error 的消息如果**同回合还有后续**，是 step 不是结尾。

**这处改了 4 次才对，每次都是靠日志推翻推断**：
1. 用 `items.lastOrNull()` 判断 → 尾部其实是 `[Msg, Err, Msg]`（wordless 失败自己也会加一行 Msg），拿到的是 Msg，永远不命中。

3. 想删掉占位行 → 索引算错，删错了行。

## 输入框逐像素对齐（重要方法论）

用户第二次指出输入框不对，说「阴影、圆角、按钮、背景都不一样，你在搞什么」。

**我之前的致命错误**：一直照 `src/renderer/src/components/Composer.vue` 的 CSS 抄数字。但**桌面 Web 版和手机 Claude App 是两套设计**，在平板这个尺寸上不能套用。所以越「按规范抄」越错。

**正确做法**：平板上**装着 Claude App 本体**（`com.anthropic.claude`），直接开它、截图、量像素。
- 启动用 `monkey -p com.anthropic.claude -c android.intent.category.LAUNCHER 1`（`am start -n ...MainActivity` 会报 Activity 不存在，真名是 `.mainactivity.MainActivity`）
- 拉图用 adb pull（`pad.py` 没有 pull，要自己 subprocess 调 ADB，并 pop 掉 `ELECTRON_RUN_AS_NODE`）

**量法（这套脚本可复用）**：
1. **框的上下边界**：取一列（如 x=2200）沿 y 扫，相邻像素差 >4 就记边界。四个边界 = 上边框、框内顶、框内底、下边框。
2. **框内内容分布**：逐行统计「暗像素数」（`sum(rgb)<520`），>3 的连续段就是一行内容。得到 `[15.8dp, 44.0dp]` 这种两个数字，直接和目标比。
3. **dp 换算**：`d = 3408/1080 = 3.156`（真机宽度 / 截图显示宽度）。

**实测真值 vs 我原来的**：
| 项 | Claude | 我原来 |
|---|---|---|
| 框高 | 79.2dp | 93dp |
| 占位距顶 | 16.5dp | 24.1dp |
| 控件行距顶 | 44.7dp | 79.9dp |
| 底色 | #FEFEFE | #FFFFFF |
| +号和麦克 | 24dp 圆 + #F0EFEC 底 | 28 方角、无底 |
| 发送 | 28dp 圆 | 28 方角（44 触摸区里） |
| 两个 pill | 胶囊 | 6dp 方角 |

**教训**：改了 8 个版本才对，因为一直在「推理 Compose 布局」而不是「量」。正确顺序是：先写量脚本 → 拿到两边数字 → 一次改到位。`heightIn` 和 padding 的相互作用算不准，量一次就有答案。

**还有一个坑**：Claude 输入框右侧留 84dp 是给系统输入法指示器（En 浮钮），不是 App 的布局——MCode 不该有这个，别去凑。

## 又一个「全部方框」的 bug

侧栏每个会话行图标都是空心方框 □。原因：路径写的是 `M5 5h14v14H5z`（闭合矩形），而 `MiIcon` 用 **Stroke** 绘制 —— 闭合路径会被描边成自己的轮廓，就是一个空框。

改成：项目会话 `M9 7 5 12l4 5M15 7l4 5-4 5`（`<>`）、非项目会话 气泡轮廓。和 Claude 的区分一致。

**教训**：`MiIcon` 全部用 stroke，所以**任何带 `z` 闭合的路径都会画成框**。写图标路径时要确认是「线」还是「面」。

## 正文列宽 + 四个「说谎」的细节

**正文列宽是这轮最大的发现**：Claude 的正文从视区边缘内缩 **40px = 12.7dp**，我用了 28dp。在 1368 宽的视区上等于**少了 100px 行宽**，所以同样的段落我更早换行、更长时间轴。

|---|---|---|
| 正文左缘 | 1000（视区 960 起） | 1016 |
| 正文宽度 | 2368 | 2359 |

**四个「说了假话」的细节**（都不是布局问题，是文案/语义）：
1. `没有匹配的会话` —— 列表本来就是空时也这么说，用户以为自己在筛选。改成按 `query.isBlank()` 分「还没有对话」/「没有匹配的会话」。
2. 发送钮 `contentDescription = "语音输入"` 在所有状态下都这样 —— 读屏会在麦克风旁边找到第二个麦克风。改成按状态给「停止/语音输入」。
3. 行图标闭合矩形被 stroke 画成空框（上一轮已记，本轮复验）。
4. 空状态文案字号 13sp 偏小，改 15sp。

**方法论补充**：
- `uiautomator` 的 text bounds 高度 **不等于** lineHeight。Compose 的 `Text` 单行时按字体度量报高度，`lineHeight` 撑的是行盒。所以**判断行距要用像素扫描**（逐行统计暗像素），不能用 bounds 高度。
- 段落节奏的正确算法：连续段落起点的 Y 差。Claude 76px(24.2dp)、我原来 76→后来 94px，调到 24sp 行高 + 0 段距后接近。

## 会话行点不动的假象

## 几个查证结果（记下来省下次时间）

1. **MCode 的平板双栏是常驻的**：`if (wide)` 分支已存在，侧栏 900px / 3408 = 26.4%，和 Claude 一致。`ModalNavigationDrawer` 只是外层壳，wide 时不渲染抽屉内容。**不是抽屉布局**。
2. **Compose 的 LazyColumn 默认不画滚动条**。所以截图里那条 x=938-947、y=1055-1175 的 3.2dp 灰条**不是滚动条**，来源未查明（优先级低，3.2dp 灰条，暂搁置）。
3. **uiautomator 对 Compose 语义树抓取不全**：截图里明明有大段文字，dump 出来只有标题。所以**量 Compose 界面必须靠像素扫描**，不能只依赖 dump。
4. **`scrollbarEnabled` 这个 modifier 不存在**（编译报 Unresolved reference）。Compose 里控制滚动条要用 `LocalScrollbarStyle` 或 AndroidView 的 `isVerticalScrollBarEnabled`。

## 密度换算错了整整一批（本轮最大的发现）

**这台平板 density 是 400dpi → 1dp = 2.5px**，我此前一直按 `3408/1080 = 3.156` 换算。
那个 3.156 是「截图名义宽 1080 与实际 3408 的比」，**根本不是 dp**。

验证方法（唯一无法反驳的）：用代码里自己设的值反推。
`contentPadding(start = 112.dp)`，面板从 925px 起 → 925 + 112×2.5 = **1205px**，截图实测 **1207px**。
若按 3.156 应是 1278px —— 图上根本没有。`wm density` 说 400，信它。

**影响**：所有从 Claude 抄来的 dp 值都放大了 26%，全部偏大四分之一。
- 正文 15sp/24sp → **18sp/30sp**（Claude 墨迹 43px=17.2dp，行距 75px=30.0dp 精确吻合）
- 正文内缩 112/99.5 → **137.6/124** dp
- 输入卡 12.7/12.0 → **116.4/106.8** dp（宽 964 → 766dp，之前宽了四分之一）
- 输入卡圆角 20 → **22.4** dp；下距注意要扣掉 16.8dp 手势条 inset
- 代码块整个重写（见下）

`.workbuddy/measure.py` 的 DENSITY 已改成 `400/160.0` 并写明原因。
